# 材质样板间进展

## 2026-09-12：外景角度映射比例修正

修复上一版横纵方向使用相同角度系数、却忽略照片2:1宽高比造成的纵向拉伸。竖向系数现在由实际图像宽高比计算，使地平线附近每弧度的横纵纹素密度一致；照片取景偏移调到0.65，客厅窗口同时可见树木、建筑和天际线。高纬度仍存在球面投影畸变，普通照片也不是真正全景，不能称全方向无变形。去掉方向向量的冗余normalize，atan比例不受向量长度影响；仍一图/一draw/两三角形。

两项单测与类型检查通过；完整Chromium旋转、整圈复原、平移不变和远深度遮挡回归通过，客厅截图已检查。没有新增贴图或几何开销，性能短测详见performance-audit.md，卡顿问题仍未完成。

## 2026-09-12：室外贴图随观察方向转动

根据用户反馈，修正室外照片锁在屏幕上的错误关系。背景仍是两个三角形，但贴图UV改为世界空间视线方向的方位角/仰角，环绕房子和抬头转头都会改变风景；位置平移不产生远景视差。沿水平方向镜像重复普通照片，避免明显左右接缝，并非真实无缝全景。保留远平面深度、室内不透明遮挡优先及透明玻璃顺序，无新增模型或纹理；背景像素增加角度计算，不能据此宣称GPU耗时完全不变。

新增真实Chromium像素回归验证水平/俯仰转动产生画面变化，回到原方向及旋转整周复原，平移差异不超过1色阶，背景独立绘制仍1次/2三角形。另验证前后绘制顺序像素一致、远裁面兼容、无页面或shader错误。客厅截图用于调整竖向取景，避免整窗只剩天空或树冠。

## 2026-09-12：地毯表面接收静态接触阴影

原有地板AO被不透明地毯遮住，椅脚下方缺少落地层次。现在显式标记地毯顶面，将该范围的烘焙采样高度抬到地毯表面，避免地毯自身把整片区域烘黑；旋转父级下的范围判断使用逆世界矩阵。地毯与地板共用同一张AO图，不增加网格、纹理数量、射线数量或渲染通道，但启用烘焙后地毯材质增加AO采样。采样点准备按行检查3ms时间片并支持取消。

仍为手动“计算房间接触阴影”，默认不开启。新增测试覆盖旋转范围、隐藏/倾斜面排除、采样高度、共享贴图和失效恢复；全部104文件/358测试及类型检查通过。完整Chromium验证取消、应用、视角切换、编辑失效与退出清理，退出后存活Worker为0；餐厅接触阴影截图已更新。该修正不是实时性能瓶颈的解决方案，也不提供柜体内部全表面烘焙。

## 2026-09-12：餐桌横向裙板顺纹

餐桌裙板与桌腿共用竖向木皮材质，原通用盒体UV导致横梁也出现沿高度的竖纹。现将x/z横梁的长度坐标分别映射到UV.v，顶面及长侧面保持米制尺度；短端面保留原映射（并非新增真实端面年轮材质）。桌面/柜门的木皮参数不变。

4/6人餐桌测试验证四条裙板长度方向UV、与腿共用材质、外包尺寸及合批后2网格/1164三角形，不增加纹理、shader采样或运行时更新。2项测试及类型检查通过，完整Chromium餐厅截图已检查，无页面错误。该修正仅改善真实木构件方向，整体参考图质感与性能目标未完成。

## 2026-09-12：窗框玻璃压条层次

窗框清口内侧增加双面玻璃压条，压条面相对原外框面内退9mm，玻璃仍居中；两侧墙体朝向均有真实安装深度。压条共用原框材质并参与已有静态合批，宽窗1082→1274三角形，单开口窗974→1070三角形；仍3个网格、同一单层双面玻璃、forceSinglePass、无transmission整场景通道，不增加纹理。窗洞外包尺寸、定位和窗台不变。

射线验证双侧压条内退深度与玻璃清口，20/80/120cm窄窗验证有限几何和三网格预算；门资产回归与类型检查通过。精细阴影客厅截图已检查，无页面错误。该改动只改善窗框构造层次，窗玻璃环境反射和整体空间光感距离参考图仍有差距；没有帧率提升声明。

## 2026-09-12：地毯连续纱束色差

固定32KB CPU采样表只生成一次，重建地毯复用字节数据，但各材质纹理仍独立拥有，释放互不影响。3项地毯测试检查128像素正负周期、颜色变化范围、纹理色彩空间、相同像素/独立纹理所有权及原有几何预算；类型检查通过。完整Chromium餐厅与精细阴影客厅截图已检查，9张本地PBR资源正常加载，无页面错误。未测得本次修改的帧率提升，也不据此宣称整体达到参考图。

## 2026-09-12：薄玻璃反射保留

普通透明材质把已计算的介质高光再次乘以低 opacity，使窗/淋浴玻璃反射过淡。薄玻璃 shader 现将已有 specular 从染色透明度中分离，并以 F0=0.04 的 Schlick 近似增加斜视覆盖；保留现有染色比例。仍走 alpha blending，不启用 transmission、场景重绘、额外环境贴图或灯光。这是轻量薄片近似，经过色调映射后并非严格能量守恒透射，也不能反射当前房间/人物。

check-thin-glass.cjs 以黑色底色隔离漫反射，实际渲染读取高光像素：普通低 alpha 为 1，新方式为 6（8-bit），两者各一次绘制。两项玻璃/淋浴结构测试及类型检查通过，客厅与淋浴截图无页面/着色器错误。结构参数、单面片双面绘制、depthWrite=false 及 transmission=0 保持。总体视觉变化细微，间接光与真实空间反射仍未解决，不视为目标完成。

静态阴影迭代：俯瞰与装修模式记录可见投影物、世界变换、几何版本、材质/剖切面和日光状态，未变化时复用日光深度图；行走模式仍每帧更新。客厅静止近景由 402 次绘制降至 159 次。人物蒙皮、自定义深度材质和位移材质不做静态推断。单测覆盖移动门板、剖切面变化、隐藏/删除物体和移动日光后的失效。

已确认自动化后端为 `ANGLE / Vulkan / SwiftShader Device (Subzero)`，即软件渲染。其 300–450 ms 帧间隔不能作为实体显卡的性能结论。开发模式在 URL 的 `#` 之前加 `?profile=1`，例如 `http://localhost:5174/?profile=1#/walkthrough/<方案ID>`，可在浏览器控制台读取 `window.roomSimProfile`（最近 300 帧）。当前诊断包含控制逻辑、其余逻辑、渲染提交、绘制次数和阴影更新标记；仍未包含准确 GPU 计时，也未完成用户硬件验收。
